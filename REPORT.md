# Отчёт по лабораторной работе №4 по PSI

## 1. Тема и обоснование

Выбран вариант Б. «Курсограф» — конвертер валют для Android с аналитикой официального курса выбранной пары. Тема позволяет сравнить настольную и мобильную реализации одной задачи. В мобильной версии отдельные маршруты для конвертера, истории за последние 7 календарных дней и истории за последние 30 календарных дней. Даты начала и конца периода входят в расчёт.

На каждом экране аналитики есть график, минимум, максимум, среднее арифметическое, абсолютное и процентное изменение, направление тенденции. Абсолютное изменение — последний курс минус первый. Процентное изменение — эта разность, делённая на первый курс и умноженная на 100. При одной котировке доступны минимум, максимум и среднее. Для изменения нужны две даты.

## 2. Язык Лаб 3 и язык Лаб 4

| Работа | Язык | Интерфейс |
|---|---|---|
| Лабораторная №3 | Python 3.12 | Tkinter для Windows |
| Лабораторная №4 | Kotlin 2.2.21 | Jetpack Compose для Android |

Мобильный проект создан с нуля. HTTP-запросы, разбор XML, расчёт кросс-курсов, кэширование, интерфейс и тесты реализованы на Kotlin. Из предыдущей работы взяты тема, список валют и источник котировок.

## 3. Источник исторических данных и ограничения

Источник — официальный XML Национального банка Молдовы по заданной дате. Один ответ включает несколько валют. Приложение делит цену на номинал и получает число молдавских леев за единицу валюты. Для кросс-курса цена исходной валюты в леях делится на цену целевой валюты в леях.

Приложение определяет текущую дату в часовом поясе Кишинёва. При первой синхронизации оно запрашивает данные за 30 календарных дат, включая текущую. Для предыдущих дней используется до четырёх параллельных запросов. Повторная синхронизация обновляет текущую дату и запрашивает пропуски, остальные успешно полученные даты берутся из кэша. [Официальные курсы НБМ](https://www.bnm.md/ro/content/ratele-de-schimb)

НБМ публикует справочные официальные курсы. У банка и обменного пункта могут быть другие цены покупки и продажи. За выходные НБМ может публиковать один и тот же курс для нескольких календарных дат. График учитывает эти даты по XML. Если ответа за день нет, точка пропускается. На графике видно количество доступных котировок. Статистика рассчитывается по полученным значениям.

Полученные котировки записываются в локальный JSON через Android `AtomicFile`. При сбое сети открывается последний успешно сохранённый диапазон с видимой датой актуальности. При первом запуске без интернета приложение сообщает об отсутствии сохранённых котировок.

## 4. IDE, инструменты и модели

Код, тесты и документация подготовлены в OpenAI Codex с моделью семейства GPT‑6. Для локального запуска проекта на Windows предусмотрена Android Studio. Сборка и unit-тесты проверены через Gradle Wrapper 8.13 с JDK 21 и Android SDK Platform 36. История проекта разделена на этапы настройки, конвертера и кэша, аналитики, тестов и отчёта.

## 5. Результаты генерации и исправления

ИИ подготовил структуру на Kotlin, три маршрута Compose и расчёт на `BigDecimal`. В первой реализации числовой парсер принимал экспоненциальную запись. Для ответа НБМ это слишком широкий формат, поэтому проверка ограничена положительными десятичными значениями по формату XML. В первой версии при нескольких ответах с одной датой курса выбиралась ранняя запись. Сейчас используется последний полученный снимок для этой даты. Для обоих случаев добавлены тесты.

В результате Gradle собрал debug APK. Прошли 17 unit-тестов, включая нормализацию номинала, обработку пустого и некорректного XML, статистику обоих интервалов, проверку суммы и восстановление сохранённой истории при сетевом сбое. Отдельная проверка источника получила 30 датированных XML-ответов НБМ подряд.

## 6. Работа с ИИ на новом языке

В настольной работе запуск и отладка состояли из Python, Tkinter и `unittest`. При переходе на Kotlin появился отдельный этап проверки совместимости Kotlin, Compose, Gradle, SDK и JDK. Для воспроизводимой сборки пришлось закрепить версии и проверить полную установку JDK с компилятором `javac`. Этот этап оказался сложнее подготовки настольного проекта.

Тестировать преобразование курсов и статистику оказалось удобно после вынесения расчётов из Android-экрана. Например, Kotlin различает обязательную котировку и результат, который может отсутствовать. В пустом периоде функция возвращает `null`. Если есть одна точка, функция возвращает минимум, максимум и среднее и оставляет изменение пустым. Такие ограничения можно выразить в типах и проверить на JVM до запуска интерфейса.

Наиболее содержательная проверка генерации связана с состоянием Android. Восстановление графика после остановки процесса проверяется отдельным сценарием. Для него нужно сначала получить курсы в эмуляторе, отключить сеть, повторно открыть приложение и проверить дату кэша и обе вкладки. Переход на Kotlin усложнил настройку и проверку жизненного цикла, а работу с состояниями и числовыми расчётами сделал более явной.
